CodeScanner · System Architecture

Iteration Until Clean

CodeScanner doesn't just flag issues — it iterates on the code itself. Three agents propose competing fixes, an evaluator picks the best one, a validator confirms it's safe, and the loop repeats until the code hits a target grade.

01 · The Core Loop

Scan → Propose → Score → Validate → Apply → Rescan

Every iteration runs the same six-step cycle. It only stops once the target grade is reached — or the run hits its iteration cap.

01 Scan Analyzers surface complexity, duplication, and structural issues.
02 Propose (×3) Agents A, B, C each draft a fix — independently, in parallel.
03 Evaluate One suggestion is scored highest and selected.
04 Validate The winner is checked for safety before touching code.
05 Apply The change is written to the codebase.
06 Rescan Grade is recalculated against the new state.
repeats until grade target is met

02 · Three Agents, One Problem

Why 3 agents, not 1

Each agent optimizes for a different goal, so they don't compete on the same axis — they compete on philosophy. That gives the evaluator real tradeoffs to score instead of a single opinion.

Agent A

Simplicity First

Minimal changes, maximum clarity, low risk.

Optimizes for Smallest, lowest-risk diff — agent_a_simplicity.py
Agent B

Architecture Focused

Long-term structure and maintainability.

Optimizes for Design patterns, decoupling — agent_b_architecture.py
Agent C

Performance Optimized

Speed and resource efficiency.

Optimizes for Parallelization, caching — agent_c_performance.py

03 · Judgment, Then Safety

Picking the winner, then checking it twice

Evaluation answers "is this a good idea?" Validation answers "is this safe to run?" — two different failure modes, two different checks, run in sequence.

Evaluation Agent

Scores all 3 suggestions on a weighted rubric and returns the highest.

Risk of errors
40%
Complexity ↓
30%
Clarity
20%
Impl. time
10%

Validator Agent

Independently re-checks the winning suggestion before it's applied.

  • Syntax validity
  • Import availability
  • Logic preservation
  • Test regression, if tests exist
  • Performance impact

04 · Shared Contract

Why agents are interchangeable

All three strategy agents inherit from a common RefactoringAgent base and speak the same two data shapes — a strategy pattern where each strategy is agent-driven.

# the problem found by the scanner
Issue
  issue_type      str
  file_path       str
  line_number     int
  severity        str
  description     str
# the fix an agent proposes
Suggestion
  agent               str
  description         str
  changes             list[str]
  complexity_reduction float
  risk_level          str
  clarity_improvement str
  estimated_time      str

05 · Beyond the Loop

A general-purpose agent framework underneath

Separate from the refactor loop, a registry and executor layer can run any agent — concurrently or chained — including three standalone agents that never touch the iteration cycle.

agent_registry.py
Defines, loads, and executes agents — including custom YAML-defined ones.
parallel_agent_executor.py
Runs multiple agents concurrently.
agent_chain_executor.py
Chains agents sequentially — one's output feeds the next.
agent_finetuner.py
Tuning and calibration logic for agent behavior.
SecurityAuditor PerformanceOptimizer DocumentationGenerator — specialized_agents.py
